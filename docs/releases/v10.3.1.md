NitroSQLite 10.3.1 makes the async APIs faster and fixes `loadFileAsync()` on a closed connection.

## Faster async calls

Async calls used to pass through several `async` functions before they reached the native promise. Each one added a promise and extra microtask turns. `executeAsync()`, `executeRawAsync()`, `executeBatchAsync()`, `loadFileAsync()` and `transaction()` now chain the native promise directly. When no transaction or other call holds the connection, a statement now starts right away instead of waiting in the queue. Errors still come back as rejected promises. [#496](https://github.com/margelo/react-native-nitro-sqlite/pull/496) [#499](https://github.com/margelo/react-native-nitro-sqlite/pull/499) [#500](https://github.com/margelo/react-native-nitro-sqlite/pull/500) [#502](https://github.com/margelo/react-native-nitro-sqlite/pull/502)

On Release builds of [sqlite-bench](https://github.com/margelo/sqlite-bench), #496 alone brought 250 point reads in flight on a Galaxy S10 from between 138 and 153 µs per query down to between 100 and 102 µs. Sequential async point reads on an iPhone 14 Pro went from about 42 µs to 37 µs.

`executeAsync()` also passed a new JavaScript callback to native code on every query, although native code only uses it for results of 256 rows or more. It now registers one row handler and passes a numeric ID with each query. [#504](https://github.com/margelo/react-native-nitro-sqlite/pull/504)

## Transactions

`transaction()` now runs `BEGIN TRANSACTION` synchronously, like `COMMIT`, because a deferred `BEGIN` takes no lock. The callback no longer waits for a round trip to the background thread, and it still starts after `transaction()` returns. `BEGIN EXCLUSIVE TRANSACTION` stays on the background thread because it can wait for another connection's lock. [#501](https://github.com/margelo/react-native-nitro-sqlite/pull/501)

## Prepared statements

A prepared statement's `executeAsync()` and `executeRawAsync()` ran on a shared thread pool that doesn't keep call order, so each call waited for the previous result. They now run on the connection's background thread in call order, like `db.executeAsync()`, so you can start several calls without waiting for each result. [#503](https://github.com/margelo/react-native-nitro-sqlite/pull/503)

## Bug fix

`loadFileAsync()` on a closed connection now returns a rejected promise instead of throwing. [#498](https://github.com/margelo/react-native-nitro-sqlite/pull/498)

## Upgrading

Update `react-native-nitro-sqlite` to 10.3.1, and update `react-native-nitro-sqlite-vec` and `react-native-nitro-sqlite-drizzle` to the same version if you use them. The prepared statement and row handler changes touch the native module, so install Pods again on Apple platforms and rebuild your native app.
