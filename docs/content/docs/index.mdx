title: Getting Started
description: Install Nitro SQLite, rebuild your React Native app, and run your first query.
---

Nitro SQLite gives React Native apps a local SQLite database on iOS, macOS, visionOS, and Android. Start by installing its native package and Nitro Modules, then open a database with `open()`.

## 1. Install the packages

Nitro SQLite is built with Nitro V1, which requires React Native 0.88 or newer with the New Architecture. iOS builds require Xcode with Swift 6.4 or newer. Install the Nitro version that Nitro SQLite was built with, because the generated native bindings must match it:

```sh
npm install react-native-nitro-sqlite react-native-nitro-modules@1.0.0-alpha.nightly.86.g15e19db42041
```

## 2. Set up the native project

The default database location needs no custom SQLite settings. Nitro V1 builds iOS dependencies with Swift Package Manager. If your project has an `ios` directory, set up or refresh the Swift packages from your app directory after adding the packages:

```sh
npx react-native spm
```

If your iOS project still uses CocoaPods, convert it first with `npx react-native spm add --deintegrate`. Android needs no additional Nitro SQLite configuration for the default setup. For a React Native macOS project, install CocoaPods from its `macos` directory. Use [Configuration](/docs/configuration) for the shared `package.json` options. The [iOS](/docs/configuration/ios), [Android](/docs/configuration/android), and [macOS](/docs/configuration/macos) pages cover platform settings and build alternatives.

## 3. Rebuild the app

An already installed binary cannot load a native module added only to JavaScript. From a standard React Native CLI project, run the native build for your platform:

```sh
npm run ios
# or
npm run android
```

If your app uses different scripts, run its equivalent native build. See the [React Native build setup](https://reactnative.dev/docs/getting-started-without-a-framework) for platform prerequisites.

For an Expo project, build a native app for your platform:

```sh
npx expo run:ios
# or
npx expo run:android
```

> [!NOTE]
> Expo Go does not include Nitro SQLite. Use a native build after adding the package.

Expo's run commands generate native directories when they do not exist. If your project keeps generated native directories, follow [Expo's prebuild guidance](https://docs.expo.dev/develop/development-builds/introduction/) to refresh them after adding a native dependency, then rebuild.

## 4. Run your first query

`open()` returns a connection bound to a database name. SQLite creates the file if it does not exist. This example creates a table, binds a value to `?`, and reads it back:

```ts
import { open } from 'react-native-nitro-sqlite'

const db = open({ name: 'app.sqlite' })

db.execute(`
  CREATE TABLE IF NOT EXISTS notes (
    id INTEGER PRIMARY KEY,
    body TEXT NOT NULL
  )
`)

const body = 'Read the docs'
db.execute('INSERT INTO notes (body) VALUES (?)', [body])

const { rows } = db.execute<{ id: number; body: string }>(
  'SELECT id, body FROM notes WHERE body = ?',
  [body],
)

console.log(rows._array)
db.close()
```

Bind user supplied values as parameters rather than putting them into the SQL string. The row generic gives `rows._array` and `rows.item(index)` a TypeScript shape; it does not validate database values at runtime. For more result details, see [parameters and results](/docs/guides/parameters-and-results).
