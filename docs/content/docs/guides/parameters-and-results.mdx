---
title: Parameters and results
description: Bind SQLite values, inspect rows and metadata, and handle query failures.
---

Pass positional values in an array for `?` placeholders. The public `SQLiteValue` type permits `boolean`, `number`, `string`, `ArrayBuffer`, and `null`. Keep table and column names in your own SQL; parameters bind values, not identifiers.

```ts
const name = 'Ada'
const age = 37

db.execute('INSERT INTO people (name, age) VALUES (?, ?)', [name, age])

const result = await db.executeAsync<{ name: string; age: number }>(
  'SELECT name, age FROM people WHERE age >= ?',
  [18],
)

for (const person of result.results) {
  console.log(person.name, person.age)
}
```

`results` is an array of row objects keyed by column name. The connection adds `rows._array` with the same rows, `rows.length`, and `rows.item(index)`. `item()` returns `undefined` outside the array bounds. For a `SELECT`, use `rows.length` or `results.length` to count returned rows. `rowsAffected` uses SQLite's last change count, which can retain an earlier write's count after a `SELECT`; use it for `INSERT`, `UPDATE`, or `DELETE`. `insertId` exposes SQLite's last insert row ID when available and can also refer to an earlier statement.

SQLite INTEGER and REAL result values both arrive as JavaScript numbers. BLOB values arrive as `ArrayBuffer`; NULL values arrive as `null`. A bound boolean is stored through SQLite's integer binding, so read it as a number and convert it in application code if needed. JavaScript numbers cannot represent every 64-bit SQLite integer exactly; choose a storage representation appropriate for identifiers that exceed the safe integer range.

## Column metadata

For a query with result columns, `metadata` maps column names to `{ name, type, index }`. The `type` reflects the declared SQLite column type, mapped to a `ColumnType` value. Expressions without a declared column type use `NULL_VALUE`; that metadata value does not mean the result itself is null.

```ts
const result = db.execute('SELECT name FROM people LIMIT 1')
const nameColumn = result.metadata?.name

if (nameColumn) {
  console.log(nameColumn.name, nameColumn.type, nameColumn.index)
}
```

The TypeScript row generic is a promise you make about your SQL, not a runtime parser. Be especially careful with nullable columns and expressions.

## Errors

The connection's JavaScript helpers normalize database failures to `NitroSQLiteError`. Async methods reject; sync methods throw. Catch the error around the operation you can recover from:

```ts
import { NitroSQLiteError } from 'react-native-nitro-sqlite'

try {
  await db.executeAsync('SELECT * FROM missing_table')
} catch (error) {
  if (error instanceof NitroSQLiteError) {
    console.error(error.message)
  } else {
    throw error
  }
}
```

See the [query result API](/docs/api/queries-and-results) for exact types.
