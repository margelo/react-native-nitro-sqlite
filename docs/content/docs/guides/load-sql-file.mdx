---
title: Load a SQL file
description: Run one SQL statement per nonempty line from an app-accessible file.
---

Use `db.loadFile(path)` or `await db.loadFileAsync(path)` to run a SQL text file that creates tables or inserts initial data. The import uses one transaction so a failed statement does not leave only part of the file applied.

## Load statements from a file

Pass an app-accessible file-system path to the SQL file. It is separate from the database's `location` option. Copy bundled assets to an accessible file path first if your asset system does not expose one. Each nonempty line runs as a statement in an exclusive transaction.

```ts
const result = await db.loadFileAsync('/absolute/path/to/seed.sql')
console.log(result.commands, result.rowsAffected)
```

## SQL file format

The file format is deliberately simple. Each nonempty line is sent to SQLite as one statement, and a line containing more than one statement fails the import. Do not split a statement across lines, put a comment on its own line, or rely on a general SQL dump parser. For example:

```sql
CREATE TABLE IF NOT EXISTS tags (id INTEGER PRIMARY KEY, name TEXT NOT NULL);
INSERT INTO tags (name) VALUES ('work');
INSERT INTO tags (name) VALUES ('home');
```

The loader counts executed lines in `commands` and adds their affected row counts in `rowsAffected`. It rolls back when a statement fails. Choose `loadFileAsync()` for a larger file to keep the database work off the JavaScript thread. Use [batch operations](/docs/guides/batch-operations) when statements need bound parameters or when you already have the commands in JavaScript.

## Import failures

SQLite can reject a statement or fail to commit the import. NitroSQLite attempts one rollback after a failed import transaction, preserving the source path and the original SQL error. Statement failures also include the one-based file line and failing command. A failed BEGIN does not trigger rollback of an existing transaction. If rollback itself fails, its error is appended to the original import error.

The managed methods throw or reject with `SQLiteError` and native category `CouldNotLoadFile`. After a successful rollback, completed statements from the file are discarded and the connection can be used again. The error includes the failing SQL text, so avoid including sensitive literal values in files whose errors may be logged.

Both methods return a [`FileLoadResult`](/api/react-native-nitro-sqlite/interfaces/FileLoadResult) with optional `commands` and `rowsAffected` numbers.
