A table stores records as rows with named columns. Its schema defines those columns and constraints such as `PRIMARY KEY` and `NOT NULL`.

## Create a table and read its rows

```sql
CREATE TABLE notes (
  id INTEGER PRIMARY KEY,
  body TEXT NOT NULL
);

INSERT INTO notes (body) VALUES ('Buy milk');
SELECT id, body FROM notes;
```

The primary key identifies each row. `NOT NULL` prevents a row from storing a missing value in `body`.

## Storage classes and type affinity

<span id="values-returned-to-javascript" />

SQLite values have five storage classes: `NULL`, `INTEGER`, `REAL`, `TEXT`, and `BLOB`. The storage class belongs to the value. In ordinary tables, a column's declared type gives it a _type affinity_, which influences conversion without generally enforcing one storage class. [STRICT tables](https://www.sqlite.org/stricttables.html) enforce column types.

SQLite stores booleans as the integers `0` and `1`. It has no separate date storage class; applications can represent dates as text or numbers. See [SQLite's datatype guide](https://www.sqlite.org/datatype3.html).

For binding values and reading JavaScript results in Nitro SQLite, see [parameters and results](/docs/guides/parameters-and-results).
